# Governance

Oráculo currently follows a maintainer-led governance model.

## Decision process

- Maintainers set scope, roadmap and release criteria.
- Small, reversible improvements may proceed through focused pull requests.
- Changes to persistence, scoring semantics, ontology, privacy boundaries, provider architecture or autonomous behavior require prior public design discussion.
- Technical decisions should record evidence, alternatives, risks and reversibility.

## Roles

- **Users** evaluate releases and report reproducible problems.
- **Contributors** propose documented, tested improvements.
- **Reviewers** assess correctness, security, privacy and maintainability.
- **Maintainers** merge changes, manage releases and enforce community standards.

Roles are earned through sustained, constructive participation. There is no automatic right to merge access.

## Project boundaries

The official project will not merge features that hide uncertainty, misrepresent heuristics as probabilities, transmit private context without disclosure or perform consequential external actions without explicit human confirmation.
